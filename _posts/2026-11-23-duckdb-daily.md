## 今日速览

- 两个不同的嵌套列问题修入主线：Parquet 过滤下推可能选错子字段；原生 STRUCT 扫描可能让子列游标错位。
- 2.0 维护分支恢复等值连接探测端 min/max 过滤；主线另行减少运行时 IN 过滤器构建中的无用扫描。
- 主线修复两类打开数据库的故障：CLI agent 模式估算 `read_duckdb` 的事务生命周期，以及存储升级后首次 checkpoint 前的一种 WAL 回放失败。

## 重要 PR

### 正确性与恢复

- [#29207：保留被提取 STRUCT 的子字段映射](https://github.com/duckdb/duckdb/pull/29207)，kevintruong，**当日合入 main**。Parquet 投影 `s.d` 时，下推到 `s.d.e` 的过滤原来可能使用外层字段位置，误读同级字段或报内部错误。作者的回归结果由错误的 ID 1、3 变回预期的 2、4，行数相同，单查 count 不足以定位。[原报告](https://github.com/duckdb/duckdb/issues/29203) 涉及 2.0.0、2.0.1 和一个开发版；报告者在修复分支复核了原查询，未据此确认已发布修复。
- [#29194：跳过全 NULL STRUCT 批次也推进子列游标](https://github.com/duckdb/duckdb/pull/29194)，dentiny，**当日合入 main**。原生表在 checkpoint、添加无关列、追加数据后，旧扫描可能把新插入的非空结构读错。修复让跳过整个 NULL 向量时子列保持对齐。与 #29207 的 Parquet 字段映射是两个独立问题。
- [#29221：CLI agent 模式在同一事务中估算并清理计划](https://github.com/duckdb/duckdb/pull/29221)，kryonix，**当日合入 main**。作者在 2.0.1 CLI 看到 `read_duckdb`（含替代扫描写法）因估算计划清理过晚而中止；受影响时可用 `-no-agent`。修的是 CLI 调用方，不改变通用 C++ API 的事务约束。
- [#28738：修复单个宏重载删除的 WAL 回放](https://github.com/duckdb/duckdb/pull/28738)，kryonix，**当日合入 main**。以 v2.1.0 存储版本提交删除、在升级后的首次 checkpoint 前退出，默认重开仍可能读到 v2.0.0 文件头，误用新语句的版本检查拒绝回放。补丁只放行该已提交操作的回放，保留新语句的检查；不解决所有新格式记录的升级持久性。

### 连接和扫描执行

- [#29010：回补 v2.0 性能修复](https://github.com/duckdb/duckdb/pull/29010)，lnkuiper，**当日合入维护分支 v2.0-cyanoptera**。恢复等值连接探测端 min/max 过滤，并回补 [#29004](https://github.com/duckdb/duckdb/pull/29004)，避免局部分组聚合因短暂出现大量唯一键而长时间跳过哈希查找；维护分支合并不等于 2.0.1 二进制已包含。
- [#29227：增量构建运行时 IN 过滤器](https://github.com/duckdb/duckdb/pull/29227)，lnkuiper，**当日合入 main**。分批收集构建端的连接键，超出去重阈值后停止构建这份 IN 列表，避免先收集整列；不会提前停止连接本身，也不扩大过滤器覆盖范围。
- [#29205：记录外部文件缓存事件](https://github.com/duckdb/duckdb/pull/29205)，dentiny，**当日合入 main**。新增 `ExternalFileCache` TRACE 事件，可区分读请求、命中和未命中并检查字节与偏移。缓存事件不等于对象存储 GET 数，需与文件系统日志或服务端指标分别对照。
- [#29225：按实际行组数调整原生扫描并行度上限](https://github.com/duckdb/duckdb/pull/29225)，lnkuiper，**当日提出，次日已合入 main**。用实际行组数给原生扫描报告的 worker 上限加一个下界，避免较小行组过多时按行数估低；仍受流水线线程限制。这不是行数估算，也不是行组裁剪。

### 另一个待确认报告

- [#29231：S3 兼容端点的逻辑导出缺少 SQL 文件](https://github.com/duckdb/duckdb/issues/29231)，harel-e，**当日提出，待分诊**。报告者在 2.0.1 CLI 的本地 S3 兼容环境看到 Parquet 写出，但缺少 `schema.sql` 和 `load.sql`，因此导入失败；其 1.5.6 对照正常。服务未具名，不代表 AWS S3 或其他服务受影响。验收备份时不要只看数据文件存在，按[官方文档](https://duckdb.org/docs/2.0/sql/statements/export)验证导出内容并导入空数据库检查。

## 方向观察（推测）

#29010 和 #29227 说明，评估动态过滤至少要分开测两件事：**构造过滤器的成本**和**过滤器实际节省的探测端工作**。对比时可固定构建端行数，改变键的去重后数量，分别观察构造开销、过滤器是否建立和探测端读量。两项改动解决不同问题，不足以推断总体提速或官方路线图。
