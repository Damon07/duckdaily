## 今日速览

- 原生与 Parquet 的多条解码路径减少了临时缓冲、重复遍历和无效解码。
- 修复 Hive 分区过滤后，窗口计数把本该排除的文件算进去的问题。
- C API V2 新增同一环境内复用数据库实例的入口；初始化时序还有后续提案。

## 重要 PR

- [#29035：优化原生与 Parquet 扫描解码](https://github.com/duckdb/duckdb/pull/29035) · **lnkuiper** · 当日合并至 main。原生 ALP/ALPRD 直接解码到输出，DICT_FSST 稀疏筛选只解码触及的组；Parquet 则改进字典、增量编码及 BYTE_STREAM_SPLIT。作者在 400 万行、单线程热扫描加聚合的微基准中，测得原生 DICT_FSST 在 1% 聚簇选择下耗时下降 15.6%，Parquet FLOAT BYTE_STREAM_SPLIT 下降 31.3%。这是特定编码和负载的结果，不是整体查询提速承诺。
- [#29058：修复分区剪枝后的窗口自连接](https://github.com/duckdb/duckdb/pull/29058) · **guillesd** · 当日新建并合并至 main。复制扫描计划时，重新绑定 Parquet 扫描会恢复已剪掉的文件，而分区过滤已从计划移除；复现中计数从正确的 2 变成 3，即使 EXPLAIN 仍显示只扫 1/2 文件。遇到没有序列化回调且文件列表已被剪枝的扫描，改回常规窗口算子。
- [#29018：在同一环境中共享数据库实例](https://github.com/duckdb/duckdb/pull/29018) · **Robinho-MR** · 当日合并至 main。新增尚不稳定的 C API V2 入口，支持同一进程的同一环境按文件复用实例，由引擎处理路径归一化及旧实例关闭的等待。当天打开的 [#29068](https://github.com/duckdb/duckdb/pull/29068)（同一作者，核查时仍 open）拟让新实例初始化完成后再供其他调用方使用，并按解析后的设置比较配置。这不是跨进程共享或复制。
- [#29039：修复多键排序下的 OFFSET 行组剪枝](https://github.com/duckdb/duckdb/pull/29039) · **mustafahasankhan** · 当日新建并合并至 main。首个排序键为 NULL 时，后续键仍可跨行组重排这些行；修复后，只有 OFFSET 能越过所有可能含 NULL 的行组时，才按该规则跳过 NULL 行组，避免返回错误行。
- [#28873：重复行集合运算可改为一次聚合](https://github.com/duckdb/duckdb/pull/28873) · **h4nsmuller** · 当日合并至 main。对相等值可安全合并的类型，`EXCEPT ALL` 和 `INTERSECT ALL` 可按行从两侧分别计数，取差值或最小值，省去两次窗口计算和一次连接；不满足条件时保留旧计划。

## 方向观察（推测）

当天的改动显示，扫描优化既在减少解码成本，也在收紧不会改变结果的剪枝条件。#29058 尤其值得拿来做回归基准：涉及文件剪枝时，同时校验返回值和实际读文件数，不能只看执行计划里的文件计数。这是对这些 PR 的观察，不代表官方路线图。
