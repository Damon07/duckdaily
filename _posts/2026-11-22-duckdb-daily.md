## 今日速览

- 有页索引的 Parquet 文件，有望用部分算术过滤直接跳过不匹配的页，而不只是靠行组统计。
- 小 `LIMIT` 的自动预读和 `FULL JOIN` 后过滤分别从读取调度和优化器顺序下手。两个作者基准都有明确的适用范围。
- 原生表有一条嵌套列错读修复：跳过全 NULL 的父向量，仍需同步推进子列游标。

## 重要 PR

- [#29188 Parquet 页索引支持函数过滤裁剪](https://github.com/duckdb/duckdb/pull/29188) · dentiny · 当日新建，open。把客户端上下文交给页级统计检查，使其能使用已有的表达式统计推导。回归用例中，排序列的 `id // 1000 = 55` 返回 1,000 行，日志断言跳过 98,464 个行位置（不是字节数）；取模过滤作为不裁剪的对照。不能由此推断任意函数都能裁剪。
- [#29190 小 LIMIT 按行数约束自动预读](https://github.com/duckdb/duckdb/pull/29190) · kevintruong · 当日新建，open。常量 `LIMIT + OFFSET` 不超过一个标准向量时，把需求穿过投影传给符合条件的无过滤扫描。自动预读按扫描顺序凑足行数；行数不可靠时回退，手动深度设置不变。作者在本地宽表上报告读取量从 148.53 MB 降至 9.37 MB；不是网络实测，也不代表带排序的任意 `LIMIT` 都能少读。
- [#29195 过滤下推时提前收窄 FULL JOIN](https://github.com/duckdb/duckdb/pull/29195) · kevintruong · 当日新建，open。若单侧过滤能排除该侧补 NULL 的行，提早转为保留另一侧的外连接，或在两侧都满足时转为内连接，让过滤进入扫描。修订版在收窄前保留两侧的合并等值键范围；Parquet 回归断言两边各只扫一个行组。合并键用例的收益主要是修复 PR 初版的回退，耗时接近干净 main；作者的选择性年龄过滤单线程用例由 33.111 ms 降到 3.036 ms，混合年龄用例则略慢。
- [#29194 保持嵌套列的扫描游标对齐](https://github.com/duckdb/duckdb/pull/29194) · dentiny · 当日新建，open。作者报告：表尾有 NULL 结构体，做 checkpoint、增加无关列后再追加非 NULL 结构体，随后跨过旧数据的扫描可能把新行的子字段读成 NULL。改动在跳过父向量时推进所有需要扫描的子列，回归检查 STRUCT 的两个字段和 UNION 的值及标签。受影响的稳定版本未核实。

## 方向观察

**推测：** 页面统计、提前过滤和按需预读正在补不同的读放大来源。三者要分别验收：有页索引不等于统计能推出边界；过滤下推不一定让两个输入都少扫；查询最后只返回几行，也不保证扫描器只发起少量预读。这是对上述 PR 的观察，不是已发布承诺。
